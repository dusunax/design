## 항목

### SEC-2.1. 루트 빌드가 공개 환경 변수 검사를 건너뜀

- 위험: SEC-1.6의 검사(`check-public-env.mjs`)는 Storybook 패키지의 `prebuild`에 걸려 있다. 루트 `pnpm build`(`pnpm -r build`)는 이 pre 스크립트를 실행하지 않는다. CI의 `check` job이 바로 이 경로로 빌드한다. `storybook build`를 직접 부르는 경로(`pnpm exec`, Chromatic CLI가 스크립트 없이 빌드하는 경우)도 검사를 거치지 않는다.
- 피해: 치명(비밀값 유출). 검사를 거치지 않으면 `STORYBOOK_*` 값이 결과물에 문자열로 들어간다.
- 필요 조건: 1개(비밀값을 `STORYBOOK_*`에 넣는 설정 실수)
- 근거:
  - `STORYBOOK_API_TOKEN=secret-xyz-123 pnpm build`가 exit 0으로 끝나고, 값이 `storybook-static/sb-addons/chromatic-com-storybook-4/manager-bundle.js`에 그대로 들어간다(2026-11-15 확인).
  - 같은 변수로 `pnpm --filter @dusunax/moa-storybook build`를 실행하면 검사가 돌고 exit 1로 멈춘다. 검사 스크립트 자체는 동작한다.
  - `VITE_*`는 코드에서 참조할 때만 결과물에 들어간다. 참조하지 않은 `VITE_KEY`는 들어가지 않았다.
- SEC-1.6 재평가: "CI와 Chromatic 빌드도 같은 `build`를 쓰므로 함께 막힌다"는 근거가 틀렸다. 검증된 방어로 인정하지 않고, SEC-1.6은 이 항목으로 옮긴다.
- 대책:
  - 검사를 pre 스크립트가 아니라 `build`·`dev` 스크립트 안에서 실행한다(`node scripts/check-public-env.mjs && storybook build`). 루트 빌드, 패키지 빌드, Chromatic의 `--build-script-name build`가 모두 같은 스크립트를 지난다.
  - `chromatic` job은 `--build-script-name build`로 이 스크립트를 쓴다. Chromatic이 스크립트를 찾지 못해 직접 빌드하는 경로를 남기지 않는다.
- 검증: `STORYBOOK_API_TOKEN=x pnpm build`가 exit 1로 멈춘다(MOA-5.0a).

### SEC-2.2. Text 링크 정규식 제곱 시간

- 위험: 링크 패턴의 `[^\]\n]+`와 `\S*`는 닫는 기호가 없으면 줄 끝까지 읽는다. 닫히지 않은 `[`나 `[a](`가 반복되면 시작 위치마다 끝까지 읽어 입력 길이의 제곱만큼 걸린다.
- 피해: 경미(탭이 잠시 멈춤)
- 필요 조건: 없음(긴 입력만 있으면 된다)
- 근거: SEC-1.2는 "제곱 시간 수준만 남는다"고 판단했다. 실측으로 규모를 확인했다(2026-11-15, Node 24, `dist/text.js`).

  | 입력 | 1만 자 | 2만 자 | 5만 자 | 20만 자 |
  |---|---|---|---|---|
  | `[a` 반복 | 22ms | 87ms | 530ms | 8.5초 |
  | `[a](` 반복 | 13ms | 49ms | 300ms | 4.9초 |
  | `*`, `**a`, `` ` ``, 섞은 입력 | — | — | — | 5ms 이하 |

- 대책: 링크 글자는 500자, 주소는 2048자까지만 링크로 읽는다(`[^\]\n]{1,500}`, `\S{0,2048}`). 같은 20만 자 입력이 92ms, 180ms로 줄었다(2026-11-15 확인). 길이를 넘는 링크는 평문으로 남는다.
- 검증: 테스트 `does not linkify overly long links`(MOA-5.0b). 시간 측정 테스트는 CI에서 불안정해 두지 않는다(SEC-1.2와 같다).

### SEC-2.3. Text 링크 글자와 실제 주소 불일치

- 위험: `[https://bank.example](https://attacker.example)`처럼 보이는 글자와 실제 주소가 다른 링크를 만들 수 있다. 프로토콜 판정(SEC-1.1)은 https끼리의 불일치를 막지 못한다.
- 피해: 제한(피싱)
- 필요 조건: 1개(프롬프트 인젝션). 사용자가 링크를 누르는 행동은 세지 않는다.
- 근거: 데스크톱 브라우저는 마우스를 올리면 실제 주소를 상태 표시줄에 보여 주지만, 터치 기기에는 이 단서가 없다. 검증된 방어로 인정하지 않는다.
- 대책:
  - `moa`는 프레젠테이션 부품이라 막지 않는다. `packages/moa/README.md` "보안" 절에 SEC-1.3과 함께 적는다(MOA-5.1).
  - 출처 허용 목록과 표시 방식은 `moa-render`에서 SEC-1.3, SEC-1.7과 함께 정한다(SEC-3).

### SEC-2.4. CI checkout이 토큰을 git 설정에 남김

- 위험: `actions/checkout`은 기본값(`persist-credentials: true`)으로 `GITHUB_TOKEN`을 `.git/config`에 남긴다. 뒤 단계에서 실행되는 의존성 코드가 이 토큰을 읽을 수 있다.
- 피해: 경미. 워크플로 권한이 `contents: read`이고 레포가 public이라, 토큰으로 할 수 있는 일이 공개 정보 읽기뿐이다.
- 필요 조건: 1개(상위 패키지 오염)
- 대책: `persist-credentials: false`를 둔다. secret이 처음 들어오는 MOA-5.8에서 `check`와 `chromatic` job에 함께 넣는다.

### SEC-2.5. 배포 파일 허용 목록 없음

- 위험: `packages/moa/package.json`에 아직 `files`가 없다. `pnpm pack --dry-run`의 결과에 `src/`, 테스트, `scripts/`, 설정 파일이 들어가고, `.gitignore`에 있는 `dist/`는 빠진다. 지금 배포하면 동작하지 않는 패키지가 나가고, 앞으로 패키지 폴더에 생기는 파일이 함께 나갈 수 있다.
- 피해: 경미. 지금 포함되는 파일은 모두 public 레포에 있는 것이고, 비밀값은 없다.
- 필요 조건: 1개(`files` 없이 배포하는 실수)
- SEC-1 정정: SEC-1 "문제없다고 본 것"의 "`files: ["dist"]` 허용 목록이라"는 플랜 기준이었다. 실제 추가는 MOA-5.1이다.
- 대책: MOA-5.1에서 `files: ["dist"]`를 넣고, MOA-5.3의 `pack --dry-run`으로 `dist/`, `package.json`, `README.md`만 들어가는지 확인한다.

### SEC-1.4. public 레포 CI 권한 (SEC-1 열린 항목)

- 확인 결과(2026-11-15):
  - `ci.yml` 트리거는 `push`(main), `pull_request`뿐이다. `pull_request_target`은 없다.
  - 최상위 `permissions: contents: read`
  - action 3개의 고정 SHA가 해당 태그의 커밋과 같다: `actions/checkout` v7.0.1, `pnpm/action-setup` v6.1.1, `actions/setup-node` v7.1.0
  - 레포 설정: 외부 기여자 워크플로 승인 필요(`all_external_contributors`), 기본 권한 읽기, 워크플로의 PR 승인 불가, `sha_pinning_required: true`, ruleset "main 보호" 활성
- 남은 일: `chromatic` job의 fork PR 조건과 Environment(MOA-5.6, MOA-5.8). 그때까지 🟡로 둔다.

## 문제없다고 본 것

- **Text 링크 판정**: 테스트 `does not linkify javascript: urls`, `blocks scheme bypasses`, `react blocks javascript: href`, `never renders raw HTML`이 통과한다. SEC-1.1의 유지 조건을 지킨다.
- **Image `src`**: `<img>`의 `javascript:` URL은 브라우저가 실행하지 않는다. 다른 출처로 보내는 referrer는 브라우저 기본 정책(`strict-origin-when-cross-origin`)에 따라 출처만 담긴다. URL로 데이터가 새는 경로는 SEC-1.3에서 다룬다.
- **MOA-3·4 부품**:
  - Modal은 트리거 근처의 `data-moa-theme` 값을 포털의 같은 속성으로 옮길 뿐, HTML로 해석하지 않는다.
  - ChoicePicker 검색은 문자열 비교만 한다.
  - StreamingText `text`, ToolCallCard `name`·`args`·`result`, MessageBubble 발화자 이름은 모두 텍스트 노드로 그려지고 React가 이스케이프한다.
- **`dist` 결과물**: 88개 파일에 소스맵이 없고, `/Users/`나 `file://` 같은 로컬 경로가 없다. `check-css.mjs`가 전역 셀렉터를 막는다.
- **의존성**: `pnpm audit`에서 알려진 취약점이 없다(2026-11-15).
- **SEC-1.8**: `pnpm-workspace.yaml`에 `saveExact: true`, `minimumReleaseAge: 4320`이 있고, `minimumReleaseAgeExclude`는 어디에도 없다.
- **SEC-1.9**: 레포와 `node_modules` 최상위에 승인된 에이전트 스킬이 없고, 스킬 승인 설정도 없다.
- **커밋 기록**: 전체 기록에 npm·GitHub·OpenAI·Chromatic 토큰 형식의 문자열, 개인 키, `.env`·`.npmrc`·`.pem` 파일이 없다.
