# SEC-3 에이전트 연결 패키지 설계 보안 점검

전제: 레포는 public이고, `moa-stream`·`moa-render`는 npm에, playground는 Vercel에 공개된다. playground 방문자는 자기 OpenRouter 키를 넣고, 키는 서버를 거쳐 OpenRouter로만 간다(DOC-11). `moa-render`가 그리는 명세와 `moa-stream`이 받는 이벤트는 모델 출력에서 오므로 프롬프트 인젝션으로 조종될 수 있다. 점검 기준 커밋은 `ff837de`(DOC-8 추가 직후)다. 아직 코드가 없어서 설계만 본다.

## 항목

### SEC-3.1. XSS로 방문자 키 탈취

- 위험: 방문자 키는 playground 페이지의 React 상태에 있다. 페이지에서 공격자 스크립트가 한 줄이라도 실행되면 키를 읽어 밖으로 보낼 수 있다. 모델이 만든 명세가 화면에 그려지므로, 렌더러에 HTML을 해석하는 길이 하나라도 있으면 프롬프트 인젝션이 곧 스크립트 실행이다.
- 피해: 치명(비밀값 유출)
- 필요 조건: 1개(프롬프트 인젝션). 렌더러가 문자열을 텍스트로만 넣는다는 방어는 아직 코드가 없어 검증되지 않았으므로 세지 않는다.
- SEC-1.10 재평가: SEC-1은 "키는 서버에만 둔다"였다. DOC-11에서 우리 키를 두지 않고 방문자 키를 서버 경유로 쓰기로 바꿨다. 서버에 둘 키는 없어졌고, 위험은 브라우저 메모리의 방문자 키로 옮겨 왔다. SEC-1.10은 이 항목으로 닫는다.
- 대책:
  - `moa-render`는 문자열을 React 텍스트로만 넣고 `dangerouslySetInnerHTML`을 쓰지 않는다(DOC-7). 테스트 `renders strings as text, not HTML`을 MOA-9.8에 넣는다.
  - 키는 React 상태에만 두고 `localStorage`·`sessionStorage`·쿠키에 쓰지 않는다(MOA-10.11).
  - playground 응답에 Content-Security-Policy를 건다(MOA-11.4a). `script-src 'self'`로 주입된 스크립트 실행을, `connect-src 'self'`와 `img-src 'self' data:`로 키를 밖으로 보내는 길을 한 번 더 막는다.
- 검증: MOA-9.8 테스트, 배포 후 응답 헤더 확인(MOA-11.6). 둘 다 통과하면 SEC-4에서 🟢로 다시 본다.

### SEC-3.2. 서버 로그·오류에 방문자 키가 남음

- 위험: 서버가 요청 전체를 로그로 찍거나, OpenRouter 오류를 그대로 응답에 담거나, 예외 메시지에 헤더가 섞이면 키가 Vercel 로그나 다른 사람이 볼 수 있는 곳에 남는다.
- 피해: 치명(비밀값 유출)
- 필요 조건: 1개(로그를 남기는 운영자 실수)
- 근거: Vercel 런타임 로그 문서의 로그 상세 항목에 요청 헤더는 없다(2026-11-22 확인). 대신 쿼리 문자열(Search Params)과 함수가 보낸 요청(Outgoing Requests)이 기록된다. 키를 URL에 넣으면 로그에 남고, OpenRouter로 보낸 요청의 헤더가 Outgoing Requests에 보이는지는 문서에 없다. 이 부분은 미확인으로 두고 MOA-11.6a에서 확인한다.
- 대책:
  - 서버는 요청 객체와 헤더를 로그로 찍지 않는다. `catch`는 고정 문구만 돌려준다(DOC-8 Global Constraints).
  - 키는 `Authorization` 헤더로만 주고받고 URL에 넣지 않는다.
  - 테스트 `never logs or returns the key`(MOA-10.6)가 `console.*`와 응답 본문에서 키 문자열을 찾는다. OpenRouter가 실패하는 경우도 포함한다.
  - 배포 후 가짜 키(`sk-or-v1-sec3-dummy` 같은 실제로 쓸 수 없는 값)로 요청을 보내고, Vercel 로그와 그 요청의 Outgoing Requests에 그 문자열이 없는지 확인한다(MOA-11.6a). 진짜 키는 쓰지 않는다.
- 검증: MOA-10.6, MOA-11.6a

### SEC-3.3. 외부 이미지로 방문자 정보 유출

- 위험: 모델이 Image `url`에 공격자 서버 주소를 넣으면, 카드를 그리는 순간 방문자의 IP, 브라우저, 화면을 본 시점이 그 서버에 전달된다. 주소에 대화 내용을 쿼리로 붙이면 내용도 샌다. 사용자가 아무것도 누르지 않아도 일어난다.
- 피해: 제한(일부 데이터 노출)
- 필요 조건: 1개(프롬프트 인젝션)
- 대책 확정 (SEC-1.3):
  - `moa-render`는 `isAllowedUrl(url, "image")`가 `true`인 `https:` 이미지만 그리고, 기본값은 모두 `false`다(DOC-7).
  - playground는 기본값을 그대로 쓴다. CSP의 `img-src 'self' data:`가 브라우저에서도 한 번 더 막는다(MOA-11.4a).
- 검증: MOA-9.8 `does not render images by default`, `renders images allowed by isAllowedUrl`

### SEC-3.4. 링크 글자와 실제 주소 불일치

- 위험: SEC-2.3과 같다. `[https://bank.example](https://attacker.example)`처럼 보이는 글자와 실제 주소가 다른 링크를 모델이 만들 수 있다.
- 피해: 제한(피싱)
- 필요 조건: 1개(프롬프트 인젝션)
- 대책 확정 (SEC-2.3):
  - `moa-render`가 Text에 넘기기 전에 링크 글자 뒤에 실제 도메인을 붙인다. 위 예는 `https://bank.example (attacker.example)`로 보인다.
  - 쓰는 쪽은 `isAllowedUrl(url, "link")`로 링크를 평문으로 바꿀 수 있다.
  - 출처 허용 목록은 기본으로 두지 않는다. 대화 화면에서 링크는 흔하고, 도메인이 보이면 사용자가 판단할 수 있다.
- 검증: MOA-9.8 `appends link domain`, `turns disallowed links into plain text`

### SEC-3.5. 모델이 그린 입력란으로 피싱

- 위험: 모델이 "API 키를 다시 입력하세요" 같은 입력란이나 창을 그려 사용자 정보를 받아 갈 수 있다. 받은 값은 action으로 서버와 모델에 간다.
- 피해: 제한(피싱)
- 필요 조건: 1개(프롬프트 인젝션)
- 대책 확정 (SEC-1.7):
  - `obscured` TextField와 Modal은 `allowSensitive`가 `true`일 때만 그린다. 기본값은 `false`이고 playground도 기본값을 쓴다(DOC-7).
  - 일반 TextField에 "키를 입력하세요"라고 쓰는 경우는 부품 종류로 구분할 수 없어 막지 못한다. `moa-render` README "Security" 절에 이 한계를 적는다(MOA-9.15).
  - playground에서 action 값이 가는 곳은 우리 서버와 방문자가 고른 모델뿐이다. 외부로 보내는 길이 없다.
- action 허용 목록 대책 변경: SEC-1.7은 action 이름을 허용 목록으로 검증하기로 했다. action은 사용자가 화면에서 한 일을 알리는 것이고, 같은 내용을 사용자가 텍스트로도 보낼 수 있다. 허용 목록이 막는 입력이 사용자 입력보다 위험하지 않으므로 이 대책은 빼고, 모양과 크기 검증만 둔다(DOC-7 "action 왕복").
- 검증: MOA-9.8 `blocks sensitive components by default`, `renders sensitive components when allowed`

### SEC-3.6. JSON Patch·데이터 모델 경로로 prototype 오염

- 위험: `ACTIVITY_DELTA`·`STATE_DELTA`의 패치 경로나 A2UI `updateDataModel`·바인딩 path에 `/__proto__/x`가 들어오면 `Object.prototype`이 바뀔 수 있다. 같은 페이지의 다른 코드가 오염된 속성을 읽으면 동작이 바뀌고, 경우에 따라 스크립트 실행으로 이어진다.
- 피해: 치명(코드 실행으로 이어질 수 있음)
- 필요 조건: 1개(프롬프트 인젝션). playground에서는 `updateDataModel`이 모델 출력에서 바로 온다.
- 대책:
  - 두 패키지 모두 경로 토큰에 `__proto__`, `constructor`, `prototype`이 있으면 적용하지 않는다(DOC-7).
  - 객체에 쓸 때는 자기 속성만 따라간다. 상속된 속성을 따라 내려가지 않는다.
- 검증: MOA-8.4 `rejects prototype paths`, MOA-9.3 `blocks prototype paths in data model`. 두 테스트는 `({}).polluted`가 `undefined`인지까지 본다.

### SEC-3.7. 공개 API 남용

- 위험: `/api/agent`는 누구나 부를 수 있다. 훔친 키를 가진 사람이 우리 서버를 중계로 쓰거나, 요청을 쏟아 Vercel 사용량을 다 쓸 수 있다. 모델 이름은 클라이언트가 정한다(DOC-12).
- 피해: 경미. 훔친 키로 비싼 모델을 불러도, 같은 키로 OpenRouter를 직접 부르면 똑같이 할 수 있어 우리 서버를 거쳐 새로 생기는 피해는 IP를 숨기는 것뿐이다. 서버가 하는 일은 `render_ui` 하나를 단 대화뿐이다. 사용량을 다 쓰면 playground가 잠시 멈춘다.
- 필요 조건: 없음
- 근거: Vercel WAF Rate Limiting은 Hobby를 포함한 모든 플랜에서 쓸 수 있다. Hobby는 프로젝트당 규칙 1개, IP 기준, 고정 창 10초\~10분이다(2026-11-22 문서 확인).
- 대책: `/api/agent`에 IP당 60초 20회 규칙 하나(MOA-11.5), 요청 본문·`messages` 상한(MOA-10.6), 키가 없으면 OpenRouter를 부르기 전에 401(MOA-10.6). 모델 이름은 형식만 검증해 이상한 문자열이 로그와 오류 문구에 들어가지 않게 한다(MOA-10.6 `rejects malformed model names with 400`). 허용 목록은 두지 않는다. 방문자가 자기 키로 고르는 모델을 막을 비용·보안상 이유가 없다.

### SEC-3.8. 큰 명세로 화면 멈춤

- 위험: 부품 수만 개, 깊이 수천 단계, 순환 참조가 든 명세는 렌더링을 멈추게 한다.
- 피해: 경미(탭이 멈춤)
- 필요 조건: 1개(프롬프트 인젝션)
- 대책: 트리 깊이 32, surface당 부품 500개(MOA-9.3 `checkSurfaces reports depth and component limits`, MOA-9.8 `stops cyclic references at depth limit`), `render_ui` 인자 64KB(MOA-10.6). playground 서버도 같은 `checkSurfaces`로 검사해 상한을 넘는 명세는 클라이언트로 보내지 않는다.

### SEC-3.9. 명세의 prop이 DOM 속성으로 그대로 전달됨

- 위험: `moa-render`가 명세의 prop을 moa 부품에 그대로 넘기면, 받은 나머지 prop을 `<button>`에 펼쳐 넣는 moa Button 때문에 명세가 DOM 속성을 정하게 된다. 명세에 `"dangerouslySetInnerHTML": {"__html": "<img src=x onerror=…>"}`가 있으면 HTML로 들어가 스크립트가 실행되고(SEC-3.1의 키 탈취로 이어짐), `style`·`className`이 있으면 화면 전체를 덮는 가짜 창을 만들 수 있다. JSON에는 함수가 없어서 `onClick` 같은 키는 실행되지 않지만, 문자열 속성은 DOM에 남는다.
- 피해: 치명(코드 실행, 비밀값 유출)
- 필요 조건: 1개(프롬프트 인젝션)
- 근거: 공격이 없어도 목록 밖 키는 들어온다. 2026-11-22 실측에서 `nvidia/nemotron-3.5-super-vl:free`와 `google/gemma-4-31b-it:free` 모두 모든 부품에 A2UI에 없는 `props` 객체(`width`, `padding`, `fontSize` 등)를 붙였다.
- 대책: `moa-render`는 부품마다 A2UI catalog prop 허용 목록을 두고, 목록에 있는 prop만 moa 부품에 넘긴다. 나머지 키는 버린다(DOC-7). 허용 목록은 `src/catalog.ts` 한 곳에만 둔다(DOC-8 File Structure).
- 검증: MOA-9.8 `passes only catalog props`, `drops dangerouslySetInnerHTML, style, className and event props`

## 문제없다고 본 것

- **서버가 부르는 주소**: OpenRouter 주소 하나로 고정이고, 요청 값으로 주소를 만들지 않는다. SSRF 경로가 없다. 테스트 `calls only the OpenRouter endpoint`(MOA-10.6)가 유지한다.
- **OpenRouter의 IP 제한**: 모든 방문자 요청이 Vercel 서버 IP에서 나가지만, OpenRouter의 IP당 제한은 키 관리·잔액 조회 엔드포인트에만 걸린다. `:free` 모델 한도(분당 20회, 하루 50회 또는 크레딧 10 이상이면 1000회)는 키의 계정 기준이다(2026-11-22 문서 확인).
- **다른 사이트에서 `/api/agent` 호출**: 다른 사이트는 방문자의 키를 모른다. 자기 키로 부르는 것은 SEC-3.7과 같다.
- **`@ag-ui/core`**: 기본 진입점은 zod도 다른 패키지도 import하지 않는다(2026-11-22, `dist/index.mjs` 확인). 정확한 버전과 3일 규칙을 따른다(SEC-1.8).
- **fixture**: 이벤트 fixture는 private 패키지 `packages/moa-fixtures`에 있어 npm에 실리지 않는다. 손으로 만든 이벤트라 비밀값이 없다.
- **모델 평가 결과**: `docs/decisions/data/2026-11-22-model-eval/`의 결과 파일에는 모델 출력만 있고 키·`Bearer`·`sk-or` 문자열이 없다(2026-11-22 확인).
- **SEC-2 열린 항목**: MOA-5에서 모두 처리된 것을 코드로 확인했다(2026-11-22).
  - SEC-2.1: Storybook `dev`·`build` 스크립트 안에서 검사, Chromatic `--build-script-name build`
  - SEC-2.2: Text 링크 길이 상한과 테스트 `does not linkify overly long links`
  - SEC-2.4: 두 job 모두 `persist-credentials: false`
  - SEC-2.5: `files: ["dist", "README.ko.md"]`
  - SEC-1.4: `chromatic` job은 push와 수동 실행에서만, `chromatic` Environment 사용
  - SEC-1.3·SEC-2.3의 README 경고: `packages/moa/README.md` "Security" 절
