# playground 모델 선택

## 결정

방문자가 모델을 고른다. 화면에 추천 모델 두 개를 보여 주고, 다른 모델 이름도 직접 입력할 수 있게 한다. 비용은 방문자 키의 계정에서 나간다(DOC-11).

- 추천 모델
  - `deepseek/deepseek-v4-flash`: 기본 선택. 빠르고 쌈
  - `openai/gpt-5-nano`: 형식을 가장 잘 지키지만 느림
- 직접 입력: 서버는 모델 이름의 형식만 검증. `제공자/모델` 꼴(`[a-z0-9._~/-]`, `:free` 같은 꼬리표 허용)이고 100자 이하
- `:free` 모델은 추천하지 않음. 직접 입력으로는 쓸 수 있음
- 도구 인자 형식은 DOC-13에서 정함

## 대안

- 서버가 `:free` 모델 고정: 서버가 무료 모델 하나를 정하고 요청의 모델 이름은 무시하는 방식
- 허용 목록: 서버가 정한 몇 개 모델 중에서만 고르게 하는 방식

## 대안 비교

| 비교할 점 | **선택: 추천 + 직접 입력** | 대안: 서버가 `:free` 고정 | 대안: 허용 목록 |
|:---|:---|:---|:---|
| 기본 모델의 형식 통과율 | **93% (DeepSeek V4 Flash)** | 50% (Nemotron) | 고른 모델에 따름 |
| 모델이 막혔을 때 | **방문자가 다른 모델로 바꿈** | 방법 없음 | 목록 안에서 바꿈 |
| 크레딧 없는 방문자 | 402. fixture 재생만 가능 | 바로 사용 | 목록에 무료가 있으면 사용 |

## 이유

- **선택: 추천 + 직접 입력**
  - 장점
    - 기본 모델이 형식을 잘 지킴
    - 방문자가 원하는 모델로 비교해 볼 수 있음. 모델에 따라 화면이 어떻게 달라지는지가 데모가 됨
    - 비용은 방문자가 고른 모델에 대해 방문자 계정에서 나감
  - 단점
    - 크레딧이 없는 방문자는 실제 모델을 쓰지 못함
    - 직접 입력한 모델은 도구를 지원하지 않거나 형식을 자주 틀릴 수 있어 안내가 필요함
- **대안: 서버가 `:free` 고정**
  - 장점
    - 크레딧 없는 방문자도 바로 사용
  - 단점
    - 무료 모델 Nemotron의 통과율이 50%라 두 번에 한 번은 화면 대신 오류가 나옴
    - Google 계열 무료 모델은 공용 용량 때문에 대부분 429
- **대안: 허용 목록**
  - 장점
    - 평가를 통과한 모델만 쓰여 화면 품질이 일정함
  - 단점
    - 목록을 고칠 때마다 배포가 필요함
    - 방문자의 모델 선택을 막을 이유가 비용·보안 쪽에 없음(SEC-3.7)

## 평가 결과 (2026-11-22)

프롬프트 다섯 개(폼, 목록, 선택지, 버튼 왕복, 카드 고치기)를 모델마다 6번씩 돌렸다. 통과는 A2UI 모양 검사와 id 참조 검사를 모두 지난 경우다. 괄호 안은 95% 구간이다. 두 인자 형식의 차이는 DOC-13에 있다. 스크립트와 요청별 결과는 [`data/2026-11-22-model-eval/`](data/2026-11-22-model-eval/)에 있다.

| 모델 | A2UI 메시지 배열 형식 | surface 하나 형식 | 중앙값 시간 | 요청당 비용 |
|:---|:---|:---|:---|:---|
| `deepseek/deepseek-v4-flash` | 27/30 (74\~97%) | 28/30 (79\~98%) | 2.5\~2.8초 | 약 $0.00008 |
| `openai/gpt-5-nano` | 30/30 (89\~100%) | 30/30 (89\~100%) | 10.7\~11.4초 | 약 $0.0007 |
| `openai/gpt-oss-20b` | 24/30 (63\~90%) | — | 3.8초 | 약 $0.00009 |
| `nvidia/nemotron-3.5-super-vl:free` | 15/30 (33\~67%) | — | 4.4초 | 무료 |

- 이 평가 전의 예비 실측(회원가입 프롬프트 하나, 17회)에서 Google AI Studio의 무료 Gemma 4 두 모델은 8회 중 7회 429

## 무료 모델을 추천하지 않는 이유

무료 모델에만 있는 제약과, 무료 모델에서 보였지만 모델 종류와 상관없는 제약을 나눠 둔다.

### 무료 모델에만 있는 것

| 제약 | 내용 | 근거 | 대응 |
|:---|:---|:---|:---|
| 공용 용량 막힘 | 제공자가 내준 무료 용량을 모든 사용자가 나눠 써서, 방문자의 사용량과 상관없이 429가 남. 오류의 `limit_source`가 `upstream_provider_shared_pool` | 2026-11-22 Gemma 4 두 모델 8회 요청 중 7회 429, 제공자는 Google AI Studio | 서버는 `RUN_ERROR`로 알리고 다른 모델을 고르라고 안내 |
| 낮은 형식 통과율 | 평가한 무료 모델 Nemotron의 통과율이 50%. 실패는 대부분 JSON 괄호 깨짐 | 위 평가 30회 | surface 하나 형식(DOC-13)으로 다시 평가해 오르면 추천을 다시 봄 |
| 계정 한도 | 방문자 계정 기준 분당 20회, 하루 50회. 크레딧을 10 이상 산 계정은 하루 1000회 | OpenRouter 한도 문서(2026-11-22) | 하루 한도는 방문자 몫 |
| 목록 변동 | 무료 모델은 날짜에 따라 생기고 빠짐. 2026-11-22 기준 도구를 지원하는 `:free` 모델 11개 | 모델 목록 API | 추천에 넣지 않으니 영향이 직접 입력에 그침 |
| 입력 기록 | 무료 모델 제공자 일부는 프롬프트를 기록하거나 학습에 쓸 수 있음 | 미확인 | playground 화면 위 안내(DOC-11) |

### 모델 종류와 상관없는 것

| 제약 | 근거 | 대응 |
|:---|:---|:---|
| 깊은 인자 구조에서 JSON 괄호 깨짐 | A2UI 메시지 배열 형식에서 유료 GPT-OSS 20B 5회, DeepSeek V4 Flash 3회(각 30회 중) | 도구 인자를 surface 하나로 줄임(DOC-13) |
| A2UI 형식 실수(`createSurface` 누락, 문자열 바인딩, `child`에 글자) | 예비 실측에서 무료 Gemma 4 31B와 유료 Gemini 2.5 Flash Lite 모두 틀림 | 시스템 프롬프트의 완성된 예시, 서버의 형식·id 참조 검증(DOC-13) |
| 목록 밖 키(`props` 객체 등) | 예비 실측에서 무료 Nemotron·Gemma 모두 한 번 이상 붙임 | `moa-render`의 prop 허용 목록(SEC-3.9) |
| 같은 모델도 매번 결과가 다름 | 예비 실측에서 Nemotron은 3회 중 첫 회만 `props`를 붙임 | 위 대응이 매번 적용됨 |

## 결론

기본 모델은 형식을 잘 지키는 저가 유료 모델로 두고, 모델 선택은 방문자에게 맡긴다.

- 추천 => DeepSeek V4 Flash(기본), GPT-5 nano
- 직접 입력 => 형식 검증만
- 무료 모델 => 추천하지 않음. surface 하나 형식으로 다시 평가해 통과율이 오르면 추천에 넣을지 다시 봄
