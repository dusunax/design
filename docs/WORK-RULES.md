# 작업 진행 규칙

모든 플랜이 공통으로 따르는 절차다. 플랜에는 ID별 Step만 쓰고 이 규칙은 반복하지 않는다.

## 흐름

1. DOC-3에서 다음 ID를 고른다. `선행`이 모두 `완료`여야 한다.
2. `게이트`가 있으면 아래 "게이트 확인"을 통과한다.
3. MOA는 최신 `main`에서 ID 이름 그대로 브랜치를 만들고, DOC-3 상태를 `진행`으로 바꿔 첫 커밋에 넣는다.
4. 플랜의 Step을 순서대로 진행한다. 끝낸 Step은 체크박스를 채운다. 체크박스는 ID 안의 진행 위치일 뿐이고, ID 상태는 DOC-3에만 둔다.
5. 마지막 Step이 끝나면 push하고, 사용자에게 확인받은 뒤 PR을 연다.
6. 사용자가 승인하면 머지한다. `main`에서 DOC-3 상태를 `완료`로, PR 칸을 링크로 바꿔 `docs:` 커밋으로 넣는다.

SEC와 DOC는 브랜치와 PR 없이 문서를 쓰고, 끝나면 DOC-3 상태를 `완료`로 바꾼다.

## 게이트 확인

`게이트`가 있는 MOA ID는 첫 Step으로 `MOA-n.0: 게이트를 확인한다`를 둔다. 아래가 모두 맞아야 `MOA-n.1`로 넘어간다. 하나라도 아니면 브랜치를 만들지 않고 멈춘 뒤 사용자에게 알린다.

1. DOC-3에서 게이트 SEC의 상태가 `완료`다.
2. 그 SEC 문서에서 반영하라고 한 항목이 모두 이 ID나 앞선 ID의 Step으로 들어가 있다.

게이트 SEC가 끝나지 않으면 선행 MOA가 끝났어도 시작하지 않는다.

## Step 번호

- MOA ID 아래 Step은 `MOA-n.k`로 번호를 매긴다. 소제목(부품 이름 등)은 Step을 묶는 이름일 뿐이다.
- 한 번 매긴 번호는 바꾸지 않는다. 사이에 끼울 때는 `MOA-2.6a`처럼 붙인다. 커밋이나 문서에 남은 번호가 다른 Step을 가리키지 않게 하기 위해서다.

## 커밋과 PR

### 언제 커밋·push하는가

| 작업 | 커밋 | push |
|---|---|---|
| 플랜의 Step 진행 | Step마다 바로 | 바로 |
| 사용자가 따로 요청한 수정 (리뷰 피드백, 디자인 조정 등) | 바로 하지 않음. 변경을 작업 트리에 모아 둔다 | 사용자가 말하면 모은 변경을 한 번에 커밋하고 push |
| PR 생성, 머지 | — | 사용자 승인 후 |
| npm 배포 | — | 사용자 승인 후 |

요청받은 수정을 하나씩 커밋·push하면 PR에 작은 커밋과 CI 실행이 쌓인다. 그래서 모아서 한 번에 올린다.

### 커밋 메시지와 PR

- 커밋 메시지와 PR 제목은 `type(scope): 한국어 설명`이다. 괄호에는 scope(`moa`, `storybook` 같은 패키지 이름)만 쓰고 설명을 넣지 않는다. 여러 패키지에 걸치면 scope를 생략한다.
- PR 제목은 설명 앞에 ID를 대괄호로 붙인다(`feat(moa): [MOA-3] 의존성 있는 부품 추가`). squash 커밋 제목이 되므로 main 기록에서도 ID가 보인다. Step 커밋에는 붙이지 않는다.
- PR 제목에는 외부 라이브러리 이름을 쓰지 않는다. 라이브러리 이름은 PR 본문에 적는다.
- PR 본문 첫 줄에 `> ID: MOA-n` 형식으로 ID를 적는다.
- 머지는 squash가 기본이다. 다르게 하는 ID는 플랜의 ID 머리에 적는다.
- changesets가 도입된 뒤(MOA-5부터)에는 PR마다 changeset을 하나 넣는다.

#### PR 본문

틀은 `.github/pull_request_template.md`다. 표기는 DOC-1 "본문 표기"를 따른다.

- 절 순서: 개요 → 변경 내용 → 스크린샷 절 → 리뷰 참고 → 테스트. 스크린샷이 없으면 스크린샷 절을 뺀다.
- 개요와 변경 내용은 불렛으로 쓴다. 불렛은 명사형으로 끝내고(`적용한다` → `적용`), 한 줄에 여러 가지가 들어가 길어지면 하위 불렛으로 나눈다. 연관 문서 불렛(`**문서**`)은 변경 내용 맨 위에 두고, 문서는 커밋 고정 링크로 건다.
- 스크린샷 절 이름은 보여 주는 대상으로 짓는다(`부품`, `파운데이션`, `마스코트`).
- 스크린샷은 레포에 커밋하지 않고 본문에 첨부한다.
- 스크린샷은 대상 하나에 표 하나다. 왼쪽 정렬한 머리 칸에 `**이름** — 설명`, 본문 칸에 이미지를 둔다. 같은 대상의 light와 dark는 한 표에 넣는다. 넓은 이미지는 위아래로, 한 장이 420px 이하면 두 열로 둔다.
- 이미지는 2배 해상도로 찍고 표시 폭을 원본의 절반(최대 800px)으로 둔다.
- 리뷰 참고에는 추가 의존성, 크기, 검증 결과를 둔다. 파일 트리는 그 아래 `### 구조`에 둔다.
- 플랜과 달라진 점, 머지 방식 안내 같은 내부 메모는 넣지 않는다.
- 테스트는 체크리스트로 쓰고, 하지 않은 일은 `[ ]`로 남긴다.

## ID를 나누거나 추가할 때

- 쓰지 않은 다음 번호를 받는다. 한 번 쓴 번호는 다시 쓰지 않는다.
- DOC-3의 맞는 자리에 행을 넣고, 플랜에 Step을 쓴다.
